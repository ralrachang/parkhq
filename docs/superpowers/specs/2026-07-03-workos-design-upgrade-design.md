# Work OS 대시보드 디자인 업그레이드 — 설계 (B안: 공유 디자인 시스템 + 구조 개편)

- 날짜: 2026-07-03
- 대상: `workos/dashboard.py` · `workos/ops_board.py` (생성기), 신규 `workos/theme.py`
- 상태: 사용자 승인 완료 (B안)

## 1. 목표와 가정

- **목표**: 두 대시보드(대시보드 미리보기 · 작업 전 점검대)를 "돈 받고 팔아도 될 것 같은" 프리미엄 SaaS급 비주얼로 업그레이드한다. Linear/Stripe 계열의 절제된 프리미엄이 기준.
- **가정(사용자 확인)**: 용도는 본인용 로컬 전용 그대로. 데모/공개용 마스킹 모드는 범위 밖.
- **성공 기준**: 두 페이지가 한 제품처럼 보인다(동일 팔레트·타이포·컴포넌트·다크/라이트 UX). 차트에 축·그리드 등 최소한의 데이터 시각화 문법이 갖춰진다. 데이터·파이프라인 변경 0.

## 2. 유지하는 제약 (설계 철학)

- 의존성 0 · 자체완결 단일 HTML · **JS 없음** (인터랙션은 `<details>`, `:has()` 등 순수 CSS)
- 생성 HTML은 민감 데이터 포함 가능 → 로컬 전용, `.gitignore(workos/*.html)` 유지
- DB 스키마·쿼리·신호 계산(`ops_signals`)·코멘트(`ops_comments`)·게이트(`verify_gate`)는 일절 변경하지 않음 — **디자인 레이어만**

## 3. 아키텍처

새 모듈 `workos/theme.py` — 두 생성기가 import하는 디자인 단일 출처.

```
theme.py
├─ TOKENS_CSS      : :root 색 토큰(기본 다크) + :root:has(#themechk:checked) 라이트 쌍,
│                    타이포 스케일, 간격/라운드 변수
├─ BASE_CSS        : reset, body, .wrap, 헤더/메타라인, 푸터
├─ COMPONENTS_CSS  : KPI 타일, 카드, 칩/배지, 테이블, 수평바, 토글 버튼
├─ CHART_CSS       : SVG 차트 공통(축·그리드·막대·라벨·호버)
├─ theme_toggle()  : 다크/라이트 토글 마크업(체크박스+라벨) 반환
├─ page_head(title): <head> + 스타일 조립
└─ chart helpers   : 일별 막대 SVG 생성(y축 눈금·그리드라인 포함) 공용화
```

- `dashboard.py` / `ops_board.py`는 페이지 고유 CSS만 자체 보유(점검대의 카드 상태색, 타임라인 등), 공통부는 theme에서 조립.
- 기존 클래스명은 가능한 유지해 diff를 최소화하되, 중복 정의는 theme으로 흡수.

## 4. 비주얼 방향

- **타이포**: Pretendard 스택 유지. 스케일 고정: h1 28 / h2 20 / 본문 15 / 보조 13 / 캡션 11.5(px). 숫자는 전부 `font-variant-numeric: tabular-nums`. KPI는 값 크게(28~32px, -0.5px 자간)·라벨 작게.
- **컬러**: GitHub 팔레트 의존 탈피, 채도 낮춘 자체 팔레트로 라이트/다크 완전 쌍 구성. 상태색 3종(활발=green/식어감=amber/방치=red)과 강조색(blue 계열)은 라이트·다크 각각 대비(WCAG AA) 확인. 구현 시 `dataviz` 스킬의 팔레트 검증 절차 적용.
- **표면**: 카드 = 1px 보더 + 미세 그림자(다크에선 그림자 대신 보더 대비), 라운드 8px 통일, 간격은 4px 배수 체계. 섹션 간 수직 호흡 확대(현 30px → 40~48px).
- **다크/라이트**: ops_board의 순수 CSS `:has()` 토글을 theme으로 옮겨 dashboard에도 동일 적용. 기본 다크(dashboard 현행 사용감 유지), 토글 위치·모양 동일.

## 5. 차트 업그레이드 (dataviz 스킬 적용)

- 일별 막대차트(양쪽 공용): y축 눈금 3~4개 + 수평 그리드라인, 값 포맷(k/M), 막대 호버 하이라이트(CSS `:hover`), 주말/오늘 구분은 범위 밖(YAGNI).
- 수평 바(프로젝트별·도구별): 트랙/필 대비 조정, 단일 시리즈 색 일관화, 라벨-값 정렬 정리.
- KPI 타일: 보조 텍스트 슬롯(예: "/ 전체 N") 스타일 정식화. 추세 스파크라인은 범위 밖(YAGNI — 데이터 로직 추가 필요).

## 6. 페이지별 변경

**dashboard.py**
- 헤더: 제목 + 메타라인(기간·파일 수·게이트 상태)을 정돈된 한 줄 구조로, 로컬 전용 배지 스타일 통일
- KPI 6개 → 위계 있는 타일(값/라벨/보조), 비용 타일은 "추정" 뱃지
- 테이블: 행 호버, 헤더 구분 강화, 우측 정렬 숫자 열 일관화
- 다크/라이트 토글 추가 (theme 공용)

**ops_board.py**
- 카드 요약부(접힌 상태)를 2줄 고정 밀도로 정돈: 1줄 = 번호·플래그·이름·칩, 2줄 = 경과일·추세·문서·담당
- 컬럼 헤더 시각 강화(카운트 뱃지화), 칩(aggbar) 스타일 theme 통일
- AI 코멘트 블록·추천 액션 블록 스타일 정제(현 구조 유지)

## 7. 검증 계획

1. `python dashboard.py` · `python ops_board.py` 재실행 — 에러 0, 바이트 수 정상 범위
2. 로컬 서버로 두 페이지 × 라이트/다크 = 4장 스크린샷 확인 (`verify` 스킬, Playwright)
3. `verify_gate.py` 실행해 데이터 레이어 무변경 확인 (게이트 16/16 PASS 유지)
4. `git status`로 `workos/*.html` 미추적 유지 확인 — 커밋 대상은 `theme.py`·생성기 2종·본 문서만

## 8. 범위 밖 (명시적 제외)

- JS 도입(테마 기억·필터·정렬·툴팁) — C안, 유료화 확정 시 재검토
- 민감 데이터 마스킹 모드(데모/공개용) — 용도 변경 시 별도 스펙
- 데이터·신호·코멘트 로직 변경, 새 지표 추가
- 스파크라인, 주말 구분 등 데이터 가공이 필요한 차트 기능
